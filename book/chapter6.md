**Основні Ідеї**

**1. IP-адресація: "Даємо Кожному Свій Паспорт"**

-   **Принцип:** Кожен мережевий пристрій (камера, NVR, світч, комп'ютер) потребує унікальної IP-адреси в межах однієї логічної мережі для ідентифікації та зв'язку. Це порівнюється з "паспортами" для людей.
-   **Типи IP-адрес:**
	- **Статичні IP (Static IP):** Адреса, маска, шлюз, DNS призначаються вручну на кожному пристрої.
		-   _Плюси:_ Стабільність, передбачуваність, легке запам'ятовування/документація, простіше налаштування доступу та інтеграцій. **Рекомендовано для камер та NVR.**
		-   _Мінуси:_ Ручне налаштування на кожному пристрої, ризик IP-конфліктів при помилці.
	-   **DHCP (Dynamic Host Configuration Protocol):** Пристрій автоматично отримує IP-адресу від DHCP-сервера (зазвичай роутера).
		-   _Плюси:_ Простота підключення (Plug-and-play), менше ризику конфліктів (при правильному налаштуванні DHCP-сервера).
		-   _Мінуси:_ **Нестабільність** - адреса може змінюватися, що "повний піпец" для NVR, який шукає камери за старими адресами, та для налаштувань доступу. **Чистий DHCP НЕ рекомендується для камер та NVR.**
	-   **DHCP Reservation (Статика через DHCP):** Компроміс. DHCP-сервер налаштовується так, щоб завжди видавати ту саму IP-адресу конкретному пристрою, ідентифікуючи його за MAC-адресою. Пристрій налаштований на отримання IP автоматично (DHCP).
		-   _Плюси:_ Поєднує зручність автоматичного налаштування з адресною стабільністю, централізоване керування адресами на роутері.
		-   _Мінуси:_ Потребує доступу до налаштувань DHCP-сервера.

>  "DHCP Reservation - це Дуже хороший варіант, особливо в мережах, де ти не єдиний адміністратор, або для спрощення початкового налаштування. Для інженерів – це часто найкращий підхід при роботі з обладнанням клієнта..."

**2. Планування Діапазонів IP та Уникнення Конфліктів**

-   **Приватні Діапазони:** Використання приватних IP-адрес (192.168.x.x, 172.16-31.x.x, 10.x.x.x), які не маршрутизуються в Інтернеті, є стандартом безпеки.
-   **Планування:** Необхідно заздалегідь скласти схему IP-адрес, виділивши окремі, **непересічні діапазони** для:
	-   Статичних адрес (камери, NVR, сервери).
	-   Діапазону видачі DHCP (комп'ютери, телефони).
-   **Уникнення Конфліктів:**
'Ніколи не призначай вручну IP-адресу, яка знаходиться в діапазоні видачі DHCP!'
-   Перевірка доступності IP перед призначенням (напр., командою ping).
-   Використання IP-сканерів для виявлення дублікатів.
-   Увага на діапазони, які можуть використовуватись ISP.

**3. Сегментація Мережі за Допомогою VLAN: "Діли і Володарюй"**

-   **Проблема:** Єдина мережа для різнорідного трафіку (користувачі, гості, телефонія, відео) створює ризики для продуктивності (широкомовні шторми, перевантаження) та безпеки (несанкціонований доступ до камер).
-   **Рішення:** **VLAN (Virtual Local Area Network)** – логічна ізоляція мереж на одному фізичному комутаторі. Трафік одного VLAN не "бачить" інший, якщо це не дозволено на маршрутизаторі.
-   **Переваги:**
	-	**Безпека:** Ізоляція камер та NVR в окремий VLAN, обмеження доступу через Firewall на маршрутизаторі.
	-   **Продуктивність:** Зменшення широкомовного трафіку, пріоритезація відеопотоку.
	-   **Гнучкість:** Логічна структуризація мережі.
	-   **Вимоги:** Потребує **керованих комутаторів (Managed Switches)**, які підтримують IEEE 802.1Q (VLAN tagging), та маршрутизатора/L3-комутатора з підтримкою VLAN для між-VLAN маршрутизації.
-   **Принцип Налаштування:** Створення VLAN ID, призначення портів як Access (з конкретним VLAN ID) або Trunk (для передачі трафіку багатьох VLAN між комутаторами/з роутером).
-   **Рекомендація:** **Настійно рекомендується використовувати VLAN** для систем відеоспостереження середнього та великого розміру (8+ камер) або в мережах з іншим важливим трафіком.

**4. Розрахунок пропускної здатності мережі: "Чи пролізе стільки відео?"**

-   **Принцип:** Відеопотік від кожної камери має певний **бітрейт** (Mbps), який залежить від:
	-   **Роздільної здатності (Resolution):** Вища роздільна здатність = вищий бітрейт (4K > 1080p).
	-   **Частоти Кадрів (FPS):** Більше кадрів = вищий бітрейт.
	-   **Кодека Стиснення (Codec):** **H.265/H.265+ значно ефективніші за H.264** (менший бітрейт при тій самій якості). **Цитата:** "Завжди використовуй H.265/H.265+, якщо підтримують і камери, і реєстратор!"
	-   Рівня стиснення/якості, типу бітрейту (**VBR/CBR**), складності сцени.
-   **Розрахунок:** Сумувати бітрейти всіх камер + додати **запас 30-50%** на пікові навантаження та інший трафік.
-   **Висновок:** Отримане число визначає **мінімальну пропускну здатність**, необхідну на ключових ділянках мережі (від світча до NVR, від NVR до роутера/Інтернету). Для більших систем може знадобитись Gigabit Ethernet (1 Гбіт/с) або вище.

> "Планування IP-адресації, сегментація через VLAN та розрахунок
> пропускної здатності – це три кити, на яких тримається стабільна і
> безпечна робота IP-відеоспостереження."

**5. Налаштування QoS для пріоритезації відео трафіку: "Даємо Відео 'Зелену Вулицю'"**

-   **Проблема:** В завантажених мережах важливий відео трафік може страждати від затримок та втрат пакетів через конкуренцію з менш важливим трафіком.
-   **Рішення:** **QoS (Quality of Service)** – механізм пріоритезації трафіку.
-   **Принцип (DSCP):** Маркування пакетів відеопотоку (зазвичай RTSP) спеціальною міткою DSCP на керованому комутаторі або камері. Мережеве обладнання розпізнає ці мітки і обробляє пакети з вищим пріоритетом.
-   **Де Налаштовувати:** Функція доступна на **керованих комутаторах** та просунутих маршрутизаторах (напр. MikroTik).
-   **Додатково:** Можна обмежувати пропускну здатність для менш важливого трафіку.
-   **Рекомендація:** Налаштування QoS **дуже бажане** в мережах, де відеоспостереження ділить канал з іншими сервісами, для підвищення стабільності відеопотоку.

**6. Мережеві порти та протоколи: "Хто куди стукає?"**

-   **Принцип:** Пристрої використовують протоколи та порти для комунікації. Розуміння їх є ключовим для налаштування безпеки та діагностики.
-   **Основні для Відеоспостереження:**
	- **HTTP (TCP 80):** Веб-доступ (незахищений).
	-   **HTTPS (TCP 443):** Веб-доступ (захищений). **Завжди надавай перевагу HTTPS!**
	-   **RTSP (TCP 554, іноді UDP):** Передача самого відеопотоку.
	-   **ONVIF (TCP 80, 8000, 5000 та інші):** Стандарт для взаємодії між пристроями різних виробників.
	-   Пропрієтарні протоколи/порти виробників.
	-   **Інші:** DHCP (UDP 67, 68), DNS (UDP/TCP 53), NTP (UDP 123), SSH (TCP 22), **Telnet (TCP 23) – має бути вимкнений!**
-   **Важливість для Інженера:** Знання портів необхідне для налаштування Firewall, Port Forwarding та діагностики проблем зв'язку.

**7. Налаштування Firewall та NAT: "Дозволити чи Заборонити?"**

-   **Firewall (Міжмережевий Екран):** Фільтр трафіку на основі правил.
-   **Функції:** Захист локальної мережі від зовнішнього доступу, контроль доступу між VLAN.
-   **Дії Інженера:** Перевірка правил при проблемах зв'язку, створення правил "заборонити все, що явно не дозволено" для безпеки.
-   **NAT (Network Address Translation):** Механізм, що дозволяє приватним IP виходити в Інтернет через одну публічну IP.
-   **Port Forwarding (Прокидання Портів):** Налаштування NAT для перенаправлення вхідного трафіку з Інтернету на певний порт внутрішнього пристрою.
-   **Використання:** Для прямого віддаленого доступу до NVR/камер (якщо не використовується P2P/VPN).
-   **РИЗИКИ БЕЗПЕКИ:** Кожен відкритий порт – потенційна дірка. **Зловмисники постійно сканують стандартні порти.**
-   **Рекомендації: Уникати Port Forwarding, якщо це можливо (використовувати P2P або VPN).**
-   Якщо використовується: НЕ прокидати порти напряму на камери (тільки на NVR/VMS), змінювати стандартні зовнішні порти, прокидати тільки необхідні порти (HTTPS, RTSP), використовувати складні паролі, обмежувати доступ за IP (якщо можливо).
-   **Подвійний NAT (Double NAT):** Проблема, що вимагає налаштування прокидання на обох роутерах або переведення одного в режим моста.

> "Розуміння QoS, портів/протоколів та принципів роботи Firewall/NAT –
> це те, що відрізняє простого монтажника від грамотного мережевого
> інженера."

**8. Схеми типових мережевих підключень**

Розглядаються типові конфігурації мережі для відеоспостереження, від найпростіших до складніших:

-   **Схема 1 (Камери напряму в NVR з PoE):** Найпростіша для малих систем (до 8-16 камер), де NVR має вбудовані PoE-порти. Камери підключаються прямо в NVR. Обмежено кількістю портів та PoE-бюджетом NVR.
-   **Схема 2 (Окремий PoE-Комутатор):** Класична "зірка" для малих/середніх систем. Камери підключаються до окремого PoE-комутатора, який з'єднаний з NVR та роутером. Більш гнучка, дозволяє використовувати керовані світчі.
-   **Схема 3 (Камери з Окремим Живленням):** Для камер без PoE. Потребує окремих блоків живлення або інжекторів для кожної камери. Більше кабелів та точок відмови.
-   **Схема 4 (Система з кількома Комутаторами):** "Дерево" або "розширена зірка" для середніх/великих об'єктів. Камери підключаються до локальних комутаторів, які з'єднані з центральним/магістральним комутатором. Масштабована, але складніша в плануванні та реалізації, вимагає керованих світчів.

**Висновки** 
Ефективне розгортання системи IP-відеоспостереження вимагає глибокого розуміння мережевих принципів. Ключовими моментами є:

-   **Ретельне планування IP-адресації**, з перевагою статичних адрес або DHCP Reservation для камер та NVR, та уникненням конфліктів.
-   **Сегментація мережі за допомогою VLAN** для систем середнього/великого розміру або в мережах зі змішаним трафіком є критично важливою для безпеки та продуктивності.
-   **Розрахунок пропускної здатності** є обов'язковим для уникнення затримок та втрат відео. Використання ефективних кодеків (H.265+) та гігабітних каналів є необхідністю для великих систем.
-   **Налаштування QoS** на керованому обладнанні значно покращує стабільність відеопотоку в завантажених мережах.
-   **Розуміння мережевих портів та протоколів** є базою для налаштування Firewall та діагностики.
-   **Обережність при налаштуванні Firewall та NAT**, з максимальним уникненням Port Forwarding на користь безпечніших методів (P2P, VPN).

Успішна реалізація IP-відеоспостереження залежить від синергії між якістю обладнання та грамотною побудовою та налаштуванням мережевої інфраструктури. Нехтування мережевими аспектами призводить до нестабільності, проблем з продуктивністю та суттєвих ризиків безпеки.


### Ключові терміни

-   **IP-адресація:** Система присвоєння унікальних числових адрес мережевим пристроям для їх ідентифікації та комунікації в мережі.
-   **Статична IP (Static IP):** IP-адреса, яка призначається пристрою вручну і залишається незмінною.
-   **DHCP (Dynamic Host Configuration Protocol):** Протокол, що дозволяє пристроям автоматично отримувати мережеві налаштування (включаючи IP-адресу) від DHCP-сервера.
-   **DHCP Reservation (Статика через DHCP):** Метод, при якому DHCP-сервер налаштовується на постійну видачу однієї і тієї ж IP-адреси конкретному пристрою на основі його MAC-адреси.
-   **Конфлікт IP (IP Conflict):** Ситуація, коли двом або більше пристроям у одній мережі призначено однакову IP-адресу.
-   **Маска підмережі (Subnet Mask):** Визначає, яка частина IP-адреси відноситься до мережі, а яка – до хоста (пристрою).
-   **Шлюз (Gateway):** Пристрій (зазвичай маршрутизатор), який з'єднує локальну мережу з іншими мережами (напр., Інтернетом).
-   **DNS (Domain Name System):** Сервіс, що перетворює доменні імена (напр., google.com) на IP-адреси.
-   **MAC-адреса (Media Access Control address):** Унікальний фізичний ідентифікатор мережевого інтерфейсу пристрою, присвоюється виробником.
-   **Приватні діапазони IP-адрес:** Діапазони IP-адрес (10.x.x.x, 172.16.x.x-172.31.x.x, 192.168.x.x), які призначені для використання в локальних мережах і не маршрутизуються в Інтернеті.
-   **VLAN (Virtual Local Area Network):** Технологія, що дозволяє логічно розділити одну фізичну мережу на кілька ізольованих віртуальних мереж.
-   **Керований комутатор (Managed Switch):** Мережевий комутатор, що дозволяє налаштовувати параметри мережі, такі як VLAN, QoS тощо.
-   **Некерований комутатор (Unmanaged Switch):** Простий мережевий комутатор без можливостей налаштування.
-   **IEEE 802.1Q (VLAN tagging):** Стандарт, що визначає метод додавання міток (тегів) до мережевих пакетів для ідентифікації VLAN.
-   **Access Port (Порт доступу):** Порт на керованому комутаторі, призначений для підключення кінцевого пристрою і належить тільки одному VLAN (трафік не тегується).
-   **Trunk Port (Магістральний порт):** Порт на керованому комутаторі, що може передавати трафік кількох VLAN одночасно (трафік тегується).
-   **Бітрейт (Bitrate):** Об'єм даних (в Мбіт/с), що генерує відеопотік за одиницю часу.
-   **Роздільна здатність (Resolution):** Кількість пікселів у зображенні (напр., 1080p, 4K).
-   **Частота Кадрів (FPS - Frames Per Second):** Кількість кадрів відео, що відображається за секунду.
-   **Кодек Стиснення (Codec):** Алгоритм, що використовується для стиснення відеоданих (напр., H.264, H.265).
-   **H.265/HEVC (High Efficiency Video Coding):** Більш ефективний стандарт стиснення відео порівняно з H.264.
-   **VBR (Variable Bitrate):** Змінний бітрейт, який адаптується до складності сцени.
-   **CBR (Constant Bitrate):** Постійний бітрейт, що підтримується на фіксованому рівні.
-   **Пропускна здатність (Bandwidth):** Максимальний об'єм даних, який може бути переданий через мережевий канал за одиницю часу.
-   **QoS (Quality of Service):** Механізми пріоритезації мережевого трафіку для забезпечення необхідного рівня якості для певних типів даних (напр., відео, голос).
-   **DSCP (Differentiated Services Code Point):** Поле в заголовку IP-пакета, що використовується для маркування трафіку з метою пріоритезації.
-   **HTTP (Hypertext Transfer Protocol):** Протокол для передачі гіпертексту, використовується для доступу до веб-інтерфейсів (порт 80).
-   **HTTPS (Hypertext Transfer Protocol Secure):** Захищена версія HTTP з шифруванням (порт 443).
-   **RTSP (Real Time Streaming Protocol):** Протокол для керування доставкою мультимедійних даних реального часу, використовується для передачі відеопотоку (порт 554).
-   **ONVIF (Open Network Video Interface Forum):** Стандарт для взаємодії між пристроями IP-відеоспостереження різних виробників.
-   **Firewall (Міжмережевий Екран):** Пристрій або програмне забезпечення, що фільтрує мережевий трафік на основі встановлених правил безпеки.
-   **NAT (Network Address Translation):** Механізм, що дозволяє пристроям у приватній мережі використовувати одну публічну IP-адресу для виходу в Інтернет.
-   **Port Forwarding (Прокидання Портів):** Налаштування NAT, що перенаправляє вхідні з'єднання з певного порту на публічній IP-адресі на певний пристрій у локальній мережі.
-   **Подвійний NAT (Double NAT):** Ситуація, коли два роутери послідовно виконують функцію NAT.
-   **PoE (Power over Ethernet):** Технологія, що дозволяє передавати електричне живлення пристроям разом з даними по одному Ethernet-кабелю.
-   **NVR (Network Video Recorder):** Пристрій для запису, зберігання та керування відеопотоками з IP-камер.
-   **VMS (Video Management Software):** Програмне забезпечення для керування системами відеоспостереження.

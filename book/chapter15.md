Системи відеоспостереження іноді мають проблеми, але більшість із них типові та мають логічні рішення. Головне – підходити до діагностики методично, від простого до складного.

### 1. Конфлікти IP-адрес

-   **Проблема:** Пристрої в мережі "сваряться" за однакові IP-адреси.
    
-   **Причини:** Двоє пристроїв мають однакову статичну IP; діапазон статичних IP перетинається з діапазоном DHCP; в мережі працює кілька DHCP-серверів (наприклад, на роутері та NAS), які видають однакові адреси.
    
-   **Діагностика:** Виконай команду `arp -a` у командному рядку, щоб побачити відповідність IP і MAC-адрес. Перевір логи DHCP-сервера на роутері ("Список клієнтів", "Журнал"). Переконайся, що в мережі працює лише один DHCP-сервер.
    
-   **Рішення:** Якщо використовуються статичні IP, зміни адресу одного з пристроїв на вільну. Якщо використовується DHCP, налаштуй DHCP Reservation на роутері, прив'язавши MAC-адресу пристрою (наприклад, камери/NVR) до певної унікальної IP за межами основного діапазону DHCP. Вимкни зайві DHCP-сервери в мережі, залишивши лише один (зазвичай, на основному роутері). Перезавантаж пристрої та роутер.
    

### 2. Проблеми з віддаленим доступом (NAT, порти, Firewall, DDNS)

-   **Проблема:** Локально все працює, але ззовні (з мобільного, іншого офісу) підключитись неможливо.
    
-   **Симптоми:** Помилки "Тайм-аут з'єднання", "Пристрій не в мережі", "Помилка підключення". Веб-інтерфейс не відкривається по публічній IP/DDNS. P2P статус "Офлайн".
    
-   **Діагностика (Йдемо по ланцюжку):**
    
    -   Переконайся, що пристрій (NVR/камера) доступний локально.
        
    -   Перевір наявність та стабільність Інтернету на об'єкті, швидкість на вихід (Upload Speed).
        
    -   Перевір мережеві налаштування самого пристрою (Шлюз, DNS).
        
    -   Для P2P/Хмари: Перевір статус в налаштуваннях пристрою (має бути "Online"). Перевір Firewall роутера, чи не блокує вихід до серверів виробника.
        
    -   Для Port Forwarding: Перевір правила на роутері (внутрішня IP/порти, зовнішні порти, протокол). Онлайн-перевірка портів (наприклад, canyouseeme.org) допоможе зрозуміти, чи порт відкритий ззовні.
        
    -   Публічна IP: Визнач свою публічну IP (наприклад, 2ip.ua). Порівняй її з WAN IP на роутері. Якщо співпадають – IP "біла" (Port Forwarding можливий). Якщо WAN IP приватна (192.168.x.x, 10.x.x.x) – IP "сіра" (CG-NAT), Port Forwarding не працюватиме. Якщо IP "біла", дізнайся, чи вона статична чи динамічна.
        
    -   Для DDNS: Перевір налаштування DDNS-клієнта (логін/пароль/хостнейм), статус оновлення. Виконай `ping твій_hostname.ddns.net`.
        
    -   Firewall: Перевір правила на роутері (вхідні з'єднання) та вбудований файрвол пристрою. Перевір файрвол на клієнтському ПК/телефоні. Уточни у провайдера, чи не блокує він порти.
        
    -   Подвійний NAT (Double NAT): Перевір WAN IP роутера. Якщо вона "сіра", а у тебе свій роутер, швидше за все, є подвійний NAT.
        
-   **Рішення:** При "сірій" IP звернись до провайдера за "білою" статичною IP, або використовуй P2P/VPN. Виправ проблеми з Port Forwarding (налаштування правил, порти, статична/зарезервована IP пристрою, дозвільні правила Firewall). При динамічній IP налаштуй DDNS. При подвійному NAT спробуй перевести модем провайдера в Bridge Mode або використовуй P2P/VPN.
    
-   **Порада безпеки:** РЕКОМЕНДУЙТЕ P2P АБО VPN ЗАМІСТЬ PORT FORWARDING – це безпечніше і часто простіше.
    

### 3. Проблеми з PoE живленням

-   **Проблема:** Камера не вмикається, індикатор не горить, або камера перезавантажується.
    
-   **Симптоми:** Камера не вмикається, індикатор PoE на світчі не горить/горить неправильно. Камера циклічно перезавантажується.
    
-   **Причини:** Перевищення бюджету PoE світча/NVR. Невідповідність стандарту PoE (камері потрібен 802.3at/bt, а порт тільки 802.3af). Довга або неякісна кабельна лінія (довше 80-90м, CCA замість міді). Поганий обтиск конекторів (RJ45). Несправність обладнання (порт, інжектор, камера).
    
-   **Діагностика:** Перевір PoE Budget/Status в інтерфейсі світча/NVR. Перевір специфікації камери та порту світча (стандарт af/at/bt, потужність W). Оціни довжину та якість кабелю. ОБОВ'ЯЗКОВО перевір кабель LAN-тестером. Спробуй підключити камеру коротким, завідомо робочим патч-кордом напряму до світча. Візуально оглянь конектори. Спробуй інший PoE-порт або інжектор. Спробуй заживити камеру від окремого БЖ (якщо підтримує).
    
-   **Рішення:** При перевищенні бюджету – зменш кількість камер або купи потужніший світч/NVR. При невідповідності стандарту – підключи до правильного порту або використовуй відповідний PoE-інжектор. При проблемах з кабелем – заміни на якісний мідний (Cat6), використовуй подовжувачі. Переобжми конектори. Заміни несправний порт/інжектор/камеру.
    

### 4. Проблеми з якістю зображення

-   **Проблема:** "Квадрати", гальма, розмитість ("мило"), чорно-біле вдень, неправильні кольори, шум.
    
-   **Причини:** Мережеві проблеми (пропускна здатність, втрата пакетів). Нестабільне живлення. Проблеми з кабелем. Неправильні налаштування камери (низький бітрейт, зависокий FPS/роздільна здатність, експозиція, баланс білого, DNR, режим "День/Ніч"). Проблеми з об'єктивом (забруднення, конденсат, розфокусування, пошкодження). Перегрів обладнання.
    
-   **Діагностика:** Перевір налаштування відеопотоків камери (кодек H.265?, роздільна здатність, FPS, бітрейт). Перевір параметри зображення (яскравість, контраст, WDR, баланс білого, DNR). Перевір режим "День/Ніч" (Авто/Колір, чутливість). Оглянь об'єктив фізично (чистий?). Якщо варіофокал – спробуй перефокусувати. Перевір мережу (`ping IP_камери -t`, завантаження світча/NVR). Перевір кабель та живлення. Перевір на перегрів.
    
-   **Рішення:** Відкоригуй налаштування відеопотоків (збільш бітрейт, зменш FPS/роздільну здатність, якщо мережа не тягне). Налаштуй параметри зображення. Скинь їх до заводських, якщо заплутався. Протри об'єктив, перефокусуй. Оптимізуй мережу/кабель/живлення. Забезпеч охолодження. Онови прошивку камери/NVR.
    

### 5. Проблеми із записом на NVR

-   **Проблема:** Немає запису або записи пошкоджені.
    
-   **Симптоми:** NVR не бачить диск ("No HDD", "Disk Error"). Диск переповнений, хоча циклічний запис увімкнено. Немає записів з певних камер/періодів. Записи биті.
    
-   **Причини:** Проблеми з HDD (поганий контакт, диск "вмирає"/здох, несумісність, неформатований). Налаштування запису (вимкнено циклічний запис-"Overwrite", неправильний розклад, не спрацьовує детекція руху). Перевантаження NVR (сумарний бітрейт вищий за пропускну здатність NVR). Камера офлайн. Збій живлення/прошивки NVR.
    
-   **Діагностика:** Перевір статус HDD в меню NVR ("Normal", "Error", "Uninitialized"), SMART статус диска. Перевір фізичне підключення кабелів SATA/живлення до диска. Переконайся, що опція "Overwrite" УВІМКНЕНА. Перевір розклад запису для проблемних камер. Якщо запис по події – перевір, чи події детектуються (журнал подій). Перевір завантаження NVR (CPU, вхідний бітрейт). Перевір, чи камери "Online" в NVR. Спробуй відтворити записи.
    
-   **Рішення:** Якщо диск не видно/помилка – перевір підключення, спробуй форматувати, якщо SMART поганий – заміни диск на новий (Surveillance Grade!). При переповненому диску – увімкни циклічний запис ("Overwrite"). Якщо немає запису – виправ розклад, налаштування детекції, переконайся, що камери онлайн. Якщо NVR перевантажений – зменш бітрейт з камер. При битих записах – перевір HDD на помилки, онови прошивку NVR, забезпеч стабільне живлення (UPS).
    

### 6. Проблеми сумісності (ONVIF, RTSP)

-   **Проблема:** NVR одного бренду не "бачить" камеру іншого, або не працюють функції (PTZ, аналітика, аудіо).
    
-   **Симптоми:** NVR не знаходить камеру. Камера додається, але статус "Offline". Відео є, але не працюють PTZ/аналітика/аудіо.
    
-   **Причини:** ONVIF вимкнено/несумісний (різні профілі S/G/T), неправильні налаштування при додаванні (протокол, порт, логін/пароль ONVIF), блокування мережею/Firewall, баги прошивки, обмеження виробника, неправильне RTSP посилання.
    
-   **Діагностика:** Перевір специфікації обох пристроїв на підтримку ONVIF/профілів. В веб-інтерфейсі камери увімкни ONVIF, створи ONVIF-користувача, запиши порт. При ручному додаванні в NVR вибери протокол ONVIF та введи правильні дані. Використовуй ONVIF Device Manager на ПК для перевірки зв'язку з камерою напряму. Спробуй відкрити RTSP-потік у VLC плеєрі. Перевір наявність свіжих прошивок.
    
-   **Рішення:** Увімкни/налаштуй ONVIF на камері правильно, використовуй правильні дані в NVR. Онови прошивки обох пристроїв. Якщо можливо, використовуй обладнання одного виробника. Якщо потрібне лише відео – додай по RTSP (але функції можуть не працювати). Перевір мережу/Firewall. Будь готовий до обмежень функціоналу при використанні обладнання різних брендів.
    

### 7. Проблеми з аналітикою (детекція руху) та аудіо

-   **Аналітика:** Хибні або відсутні спрацювання.
    
    -   **Причини:** Неправильні налаштування зон, чутливість, розмір об'єкта, погодні умови, застаріла прошивка.
        
    -   **Рішення:** Відкоригуй зони/чутливість, використовуй фільтрацію за розміром або AI-детекцію, онови прошивку.
        
-   **Аудіо:** Немає звуку або він поганий.
    
    -   **Причини:** Аудіо вимкнено в налаштуваннях (камера/NVR), несумісний кодек, неправильні рівні гучності, фізичне пошкодження, проблеми з мережею.
        
    -   **Рішення:** Увімкни аудіо в налаштуваннях, вибери сумісний кодек (напр., G.711), відрегулюй рівні, перевір підключення/обладнання.
        

### 8. Апаратні та Програмні збої

-   **Перегрів:** Пристрій гарячий, зависає/перезавантажується.
    
    -   **Причини:** Погана вентиляція, пряме сонце, висока температура середовища.
        
    -   **Рішення:** Забезпеч вентиляцію, перемісти, використовуй термокожухи.
        
-   **Пошкодження об'єктива:** Плями/подряпини, розмиття, що не виправляється.
    
    -   **Причини:** Удар, вандалізм.
        
    -   **Рішення:** Зазвичай заміна камери.
        
-   **Збій Прошивки:** Пристрій не завантажується, інтерфейс глючить, функції не працюють.
    
    -   **Причини:** Невдале оновлення, несумісна версія.
        
    -   **Рішення:** Перезавантаження, скидання налаштувань (Hard Reset), повторне оновлення, відновлення через TFTP (складніше), сервісний центр.
        
-   **Проблеми з Хмарою/P2P:** Статус "Offline", не підключається.
    
    -   **Причини:** Проблеми на стороні сервісу, Інтернет на об'єкті, блокування Firewall'ом, проблеми з реєстрацією.
        
    -   **Рішення:** Зачекай (якщо проблема сервісу), виправ Інтернет/Firewall, перереєструй пристрій.
        

### 9. Інструменти діагностики

Для ефективної діагностики використовуй інструменти:

-   **Фізичні:** Кабельний тестер (LAN Tester) (перевірка жил, обтиму), Мультиметр, PoE-тестер (перевірка PoE), Інструменти для обжиму, Тестовий монітор.
    
-   **Програмні (на ПК):** Утиліти виробника (SADP, ConfigTool) (пошук, активація, зміна IP), IP-Сканери (пошук пристроїв, IP/MAC, порти), Команди ОС (`ping`, `arp -a`, `tracert`), Wireshark (для просунутих, аналіз трафіку), ONVIF Device Manager (ODM) (перевірка ONVIF-сумісності), VLC Media Player (перевірка RTSP).
    

Пам'ятай, що існують також таблиці типових проблем та кодів помилок, які можуть слугувати швидкою шпаргалкою, але конкретні повідомлення можуть відрізнятись залежно від виробника.

### Висновок

Більшість проблем вирішуються методичним підходом. Починай з фізики (живлення, кабелі, індикатори), потім мережа (IP, ping), потім налаштування софту. Використовуй інструменти. Розумій причини, щоб уникнути проблем у майбутньому.

### Термінологія:
-   **Діапазон DHCP (DHCP range):** Пул IP-адрес, які DHCP-сервер може автоматично видавати пристроям у мережі.
-   **`arp -a` (arp -a command):** Команда в командному рядку операційної системи (Windows, Linux, macOS) для відображення ARP-таблиці, яка показує відповідність між IP-адресами та фізичними MAC-адресами пристроїв у локальній мережі. Допомагає виявити дублювання IP.
-   **CCA (Copper Clad Aluminium) кабель:** Дешевий алюмінієвий кабель, покритий тонким шаром міді. **Не рекомендується для PoE** через вищий опір та меншу надійність порівняно з повністю мідним кабелем.
-   **Втрата пакетів (Packet loss):** Ситуація, коли частина даних (пакетів) губиться під час передачі по мережі. Може призводити до "квадратів", завмирань та інших спотворень відео.
-   **DNR (Digital Noise Reduction / Цифрове Шумозаглушення):** Технологія в камерах, що зменшує візуальний шум на зображенні, особливо при низькій освітленості.
-   **Конденсат (Condensation):** Утворення крапель вологи на об'єктиві камери або всередині її корпусу через перепад температур, що призводить до розмитого зображення.
-   **`ping IP_камери -t` (ping <camera_IP> -t command):** Команда для безперервного пінгу IP-адреси камери. Допомагає оцінити стабільність зв'язку та виявити втрату пакетів.
-   **Сумарний бітрейт (Total bitrate) камер:** Загальна швидкість потоку даних від усіх підключених до NVR камер. Якщо вона перевищує пропускну здатність NVR, можуть виникати проблеми із записом.
-   **Кабелі SATA/живлення (SATA/power cables) для HDD:** Кабелі, що використовуються для підключення жорсткого диска до материнської плати (SATA-кабель для даних) та блоку живлення (кабель живлення) всередині NVR.
-   **Завантаження NVR (CPU, вхідний бітрейт) (NVR load (CPU, incoming bitrate)):** Показники завантаженості процесора та мережевого інтерфейсу NVR. Високі значення можуть вказувати на перевантаження системи.
-   **Профілі ONVIF (S/G/T) (ONVIF Profiles S/G/T):** Набори специфічних функцій стандарту ONVIF. Сумісність пристроїв різних виробників залежить від підтримки ними однакових або сумісних профілів (наприклад, Profile S для базового відео, Profile G для запису на карту пам'яті, Profile T для розширеного відео та аналітики).
-   **ONVIF-користувач (ONVIF user):** Окремий обліковий запис, що створюється в налаштуваннях камери спеціально для доступу через протокол ONVIF. Має свої логін та пароль.
-   **ONVIF Device Manager (ODM):** Безкоштовна програма для ПК, що дозволяє знаходити ONVIF-сумісні пристрої в мережі, переглядати їхні параметри та перевіряти сумісність функцій.
-   **VLC плеєр (VLC player):** Популярний безкоштовний медіаплеєр, який може відкривати та відтворювати RTSP-потоки з IP-камер, що корисно для тестування доступності потоку.
-   **Відновлення через TFTP (TFTP recovery):** Метод відновлення прошивки пристрою (зазвичай в аварійних ситуаціях, коли пристрій не завантажується нормально) за допомогою TFTP-сервера та спеціального файлу прошивки.
-   **PoE-тестер (PoE tester):** Прилад для перевірки наявності та параметрів живлення PoE на кабелі або порту комутатора.
-   **`tracert` (traceroute command):** Мережева утиліта командного рядка, що показує маршрут проходження пакетів даних до вказаного вузла в мережі та затримки на кожному проміжному маршрутизаторі. Допомагає діагностувати проблеми зі зв'язком.
-   **Wireshark:** Потужний безкоштовний аналізатор мережевих протоколів, що дозволяє перехоплювати та детально аналізувати весь мережевий трафік. Використовується для глибокої діагностики складних мережевих проблем.
